Field notes

Authority
All balloon physics and radio-link detection run server-side in sim-server. The browser is a thin renderer that reconciles Cesium entities against whatever it's sent and forwards user actions as REST commands — it computes nothing itself.
Single wind fetch
sim-server is now the sole client of wind_backend.py. It fetches the field once at startup, holds it as a shared Arc, and re-serves it over its own GET /api/wind-levels. The browser fetches its (arrows-only) copy from sim-server in the background, not from Python directly — one fetch to Python, one payload in memory.
Paused, synced
Pause state and the horizon-refraction coefficient both live on World and are broadcast in every Snapshot, so all connected tabs stay in sync. Controls POST the desired change and wait for the server to echo it back rather than flipping optimistically, avoiding races with in-flight snapshots.
Not in the loop
weather-data-server/get_wind_data.py is an older, separate prototype script — not part of the running app. The live backend is wind_backend.py.
