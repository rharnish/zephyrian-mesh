Field notes

Authority
All balloon physics, radio-link detection, and the comms protocol run server-side in sim-server. The browser is a thin renderer that reconciles Cesium entities against whatever it's sent and forwards user actions as REST commands — it holds no simulation state of its own.
Belief vs. truth
link_detection.rs computes the true connectivity graph; the running protocol's discovery half computes what each balloon believes it can reach, from signals it actually received — beacon.rs, aodv.rs or linkstate.rs depending on discovery=, and nothing at all under epidemic, which declares no route beliefs. Both ride on every Snapshot — the gap between them is where the interesting failures live, and it's what the belief-vs-truth overlay renders.
Single wind fetch
sim-server is the sole client of wind_backend.py. It resolves the field once at startup — from the on-disk cache when there is one, fetching from Python only on a miss — holds it as a shared Arc, and re-serves it over its own GET /api/wind-levels. The browser fetches its (arrows-only) copy from sim-server in the background, not from Python directly — one fetch to Python, one payload in memory.
Paused, synced
Pause state and the horizon-refraction coefficient both live on World and are broadcast in every Snapshot, so all connected tabs stay in sync. Controls POST the desired change and wait for the server to echo it back rather than flipping optimistically, avoiding races with in-flight snapshots.
Falling behind
Every Snapshot carries serverTimeMs. A client that falls behind is sent the newest snapshot rather than a growing backlog, and the frontend surfaces its own view lag rather than silently drifting.
