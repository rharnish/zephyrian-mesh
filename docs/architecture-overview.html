cesium-dirigible — architecture (overview)

three processes, started together by ./run-all.sh

client

Browser — Vite + CesiumJS

Renders the globe, balloons, towers, radio links, and the belief-vs-truth overlay. Holds no simulation state — reconciles whatever sim-server sends and forwards user actions back to it.

WS + REST live snapshots over WebSocket (balloons, towers, edges, believed connectivity, mesh health, paused, serverTimeMs); user actions (add tower, set balloon count, pause…) over REST
sim-server

Rust — Axum, authoritative

Owns the one true simulation state: balloon physics, wind advection, true radio-link detection, and the comms protocol — beacons, believed connectivity, and store-and-forward telemetry bundles. Broadcasts a snapshot every tick. Also re-serves its wind data to the browser.

GET wind data sim-server fetches once at startup, falls back to zero wind if unavailable; the browser now fetches its own (arrows-only) copy from sim-server, not from Python
weather-data-server

Python — FastAPI + xarray

Serves ERA5 pressure-level wind data. sim-server is now its only client — the browser no longer talks to it directly.
